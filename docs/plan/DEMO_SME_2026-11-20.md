## 5. Showing the SQL agrees with the answer (optional, high value)

This is the strongest thing to show an SME: the number Spire quotes can be
traced to a SQL statement that returns the same number.

Step 1 — print the SQL:

```bash
/home/bhagavan/virtenv/spire/bin/python scripts/promptkit.py --run \
  --prompt "Show me the account balance for customer ABC Application Software" \
  --show-sql
```

Step 2 — run that SQL on the database:

```bash
./runsql.sh "SELECT CA.CUST_ACCOUNT_ID, CA.ACCOUNT_NUMBER, HP.PARTY_NAME,
NVL((SELECT SUM(S.ACCTD_AMOUNT_DUE_REMAINING) FROM AR_PAYMENT_SCHEDULES_ALL S
     WHERE S.CUSTOMER_ID = CA.CUST_ACCOUNT_ID), 0) OPEN_RECV,
NVL((SELECT SUM(S.ACCTD_AMOUNT_DUE_REMAINING) FROM AR_PAYMENT_SCHEDULES_ALL S
     WHERE S.CUSTOMER_ID = CA.CUST_ACCOUNT_ID AND S.CLASS IN ('INV','DM')
       AND S.DUE_DATE <= TRUNC(SYSDATE)), 0) TXNS_DUE
FROM HZ_CUST_ACCOUNTS CA
JOIN HZ_PARTIES HP ON HP.PARTY_ID = CA.PARTY_ID
WHERE HP.PARTY_NAME = 'ABC Application Software'"
```

Expected: `28155.56` and `15249.95` — **the same two numbers** Spire
printed. That equality is the point.

## 6. How to run `runsql.sh`

```bash
./runsql.sh "SELECT ... FROM ..."          # inline SQL
./runsql.sh -f my_query.sql                # SQL from a file
FORMAT=csv ./runsql.sh "SELECT ..."        # CSV instead of a table
```

Rules that matter:

- **One statement per call.** A trailing `;` is fine (it is stripped), but
  two statements in one call will fail.
- Needs `IKS_FUSION_USERNAME` / `IKS_FUSION_PASSWORD` in the environment
  (already set in this shell).
- It runs against the **pod** via BI Publisher — expect a few seconds per
  query.
- Keep `SELECT` statements. This is a report runner, not a scratchpad.

## 7. Do NOT demo these tomorrow

| Prompt | Why |
|---|---|
| `Show receipts for ABC Corporation Americas at Santa Clara` | **Answers "No receipts found" although 742 exist.** Known open defect (F-077). The site filter runs client-side over the newest 500 rows, which are all site-null. Skip it. |
| Any "receipts at site X" variant | Same defect. |
| Anything asking for a tax line's `CustomerTransactionLineId` | Known id-space mismatch (F-070 open item). |

Also note, if the SME asks about receipts generally: a **count** question
may look higher than the Fusion UI shows, because the emitted SQL spans
all business units while Fusion's REST view is scoped to one (F-076).
That is a known, documented difference — say so plainly rather than
improvising.
