## V0 — Fix statement

`src/spire/nl_parser/context/payables/b_invoice_date.sysprompt`'s
RELATIVE RECENT rule gains a days-to-whole-months conversion clause for
`invoices in the last N days` where N is not a multiple of 30, and
`src/spire/nl_parser/context_assembly.py::_SYSTEM_PROMPT_PREAMBLE`'s
byte-equality mirror is updated identically — so the model emits an
integer `{"months": M}` value (M = ceil(N/30)) rather than a fractional
months value the planner rejects.

## Deviations from the F-NNN entry's suggested fix

One, on site count only.

The entry named a single site:
`src/spire/nl_parser/context/payables/b_invoice_date.sysprompt`. Two
files changed. The second is
`src/spire/nl_parser/context_assembly.py::_SYSTEM_PROMPT_PREAMBLE`, the
byte-equality mirror that
`tests/test_parser_context_assembly.py::test_module_constant_matches_literal_oracle`
asserts against. Editing the sysprompt without moving the mirror
breaks that oracle. This is the same second-site pattern that F-048
and F-049 followed.

The fix shape itself matches the entry's Shape 1 (teach the
conversion). Shape 2 (a `created_in_last_n_days` filter type) is not
implemented — see "Not checked" for the follow-up.

## Not checked

- **The `days` filter type (Shape 2).** The entry named two candidate
  shapes. Shape 1 (round up to whole months) is landed. Shape 2
  (a `created_in_last_n_days` filter with a days-precision cutoff) is
  not. If callers want exact day bounds rather than rounded-up
  months, Shape 2 remains a follow-up.
- **Rounding up to 1 month for any N <= 30.** 7, 14, and 30 tested.
  `1 day`, `3 days`, and `29 days` were not; each rounds to 1 under
  the current rule.
- **Rounding up at the 30-day boundary.** `31 days` rounds to 2
  months under the new rule. Not tested. The rule is monotone but the
  boundary behaviour is unverified.
- **The same shape on PurchaseOrder.** F-055's reproduction section
  did not test whether `purchase orders created in the last 7 days`
  fails the same way pre-fix. The Invoice path is fixed; whether
  `b_po_created_date.sysprompt` has the same gap is a separate
  question.
- **The 1/10 parser refusal from F-055's original reproduction.**
  N=20 post-fix shows 0 refusals; whether that 1/10 was the JSON-mode
  stochastic mode (F-052's shape) is not investigated.
