## V0 - Fix statement

Add a post-parse correction helper `_extract_period_bounds(prompt, intent)`
in `src/spire/nl_parser/parser.py`, of the same class as
`_extract_invoice_number` / `_extract_list_cap` / `_has_country_column_phrasing`,
that detects the period-anchored phrasings `this year` / `this quarter` /
`this month` / `last year` in the raw prompt and, when the intent carries an
`aggregate` block with `op='by_supplier'`, overrides its `date_from` /
`date_to` values with calendar bounds computed from `date.today()` in Python -
so an aggregate intent cannot carry an absent or wrong period window on a
period-anchored prompt.

## Design decision

Post-parse correction (Option B), not a sysprompt rule (Option A).

The sysprompt's `by_supplier` bullet asks the model to compute ISO bounds
itself, and it names no period-anchored phrasing (finding S3). The codebase's
other date rules explicitly say `Do NOT compute the date yourself`; the
aggregation bullet violates that. F-055 taught a conversion that has one
answer (`7 days -> 1 month`); period phrases need a reference date, which the
endpoints reference says the LLM does not have. F-058's reproduction shows
three runs producing three different model outputs (None, 2025-01-01,
correct), which is the expected behaviour when the model is guessing. The
deterministic correction removes the model's guesswork entirely.

A follow-up may add the phrasing family to `m_aggregation.sysprompt` for the
model's benefit — deferred; not part of this fix.

## Scope

Only fires when:
- `intent.aggregate is not None`, AND
- `intent.aggregate["op"] == "by_supplier"` (the only aggregate op that
  accepts `date_from` / `date_to` per `_AGGREGATION_PARAMS`), AND
- the raw prompt contains one of the four period-anchored phrases.

Does not touch:
- `po_value_by_supplier`, `po_count_by_status`, `open_po_summary`,
  `exposure_ranking`, `receipt_method_distribution`, `top_invoices_by_amount`
  - none accept a date range.
- List-path date filters (`older_than_n_months`, `created_in_last_n_months`,
  `invoice_date`, `created_before`, `created_since`) - F-046/F-047/F-048/F-049
  own those.
- Non-period phrasings on `by_supplier` - `in 2022`, `in the last 6 months`,
  etc. - which already work through the existing rules.
