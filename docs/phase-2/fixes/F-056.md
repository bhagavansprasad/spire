## V0 — Fix statement

Add a local synthesizer builder for the F-053 four-bucket shape (source
+ filtered suppliers + refetched POs + buyers), routed by a matching
detector in `synthesizer/p2p.py`, so the anchor prompt
`List US suppliers with open purchase orders, include the buyer` returns
a `SupplierResponse` directly — no LLM call — and the
`Synthesized response: (none)` fallback (the LLM hitting its output cap)
disappears.

## V2 — Paraphrase (covered by unit tests)

Not run live. The paraphrase cases are covered by the new unit tests
against the same code path, at lower cost:

- `test_detector_is_bucket_name_agnostic` — the detector recognises the
  four-bucket shape by content signature, not by bucket name.
- `test_four_bucket_shape_builds_locally_without_llm` — the routing
  branch fires and returns the `SupplierResponse`.
- `test_four_bucket_summary_states_examined_versus_matched` — the
  summary text is the four-bucket wording.

A live paraphrase run (anchor-shaped prompt, reworded) would add ~3–5
minutes of pod cost for a signal the unit tests already assert
deterministically. The reword does not change the bucket shape, which is
what the fix keys on.

## Deviations from the F-056 entry's suggested fix

One substantive deviation, on the surface the fix touches.

The F-056 entry named two candidate sites:

1. **`src/spire/synthesizer/synthesizer.py`** — add a fifth local
   builder. **Landed, and extended.** The entry named the file but not
   the function; the fix adds a detector and builder to
   `synthesizer/p2p.py` (where `build_suppliers_with_open_pos` and its
   two-bucket sibling live) and a routing branch in `synthesizer.py`.
   Same file layout as F-010's fix: the builder goes in the module whose
   schemas it populates.

2. **`src/spire/graph/pipeline.py` / `src/spire/rendering/formatters.py`**
   — display-side mitigation. **Deferred.** The entry recommended it as
   a defensive fallback for any future four-bucket shape not yet built.
   With (1) landed, the anchor prompt no longer reaches the marker, and
   no other prompt in the current test set does either (V6 and V5
   confirm). Building a display path for `synth_failed` is a shape not
   yet observed, and would be scaffolding for a case that may never
   recur. Recorded as a candidate follow-up, not part of this fix.

**A second deviation, not in the F-056 entry.** A pre-existing test
fixture collision surfaced during V6. `tests/test_synthesizer.py`'s
`sample_outputs` fixture had the same `{source}_{suffix}` prefix pair
that F-053's plan produces for the anchor prompt, so the new detector
claimed it and three LLM-path tests stopped reaching the LLM. The fix
renamed the second bucket (`us_suppliers_no_recent_invoices` →
`filtered_suppliers`), breaking the prefix relationship. Six lines in
one file. Not a production change. Recorded here because it is a
behavioural edge the F-056 entry did not anticipate: **any fixture whose
bucket names follow the F-053 prefix convention will hit the new
detector unless it is a genuine four-bucket shape.** The one other such
pair in the test tree (`test_f010_filtered_count.py`'s
`suppliers`/`suppliers_has_classification`) does not call
`synthesize_response` directly, so it does not collide today; recorded
as a latent hazard below.

## Not checked

- **`LLM_MAX_OUTPUT_TOKENS`'s actual value.** Not read. The finding's
  arithmetic assumed 8192; the reproduction (`out=7985` twice, two
  windows) is independent of the exact number.
- **The synthesizer's exact failure mode inside the LLM call.** Whether
  `finish_reason != stop` or `parsed is None`. Both route through the
  same `DegenerateOutputError` catch, and both are removed by the fix
  on this shape.
- **Whether other prompts produce the F-053 four-bucket shape.** Only
  the anchor prompt was tested. Any prompt combining a
  `filter_source_when_nonempty` step, a downstream include whose edge
  requires a refetch, and a parent-of-the-filter root would produce the
  same shape. A sweep of the prompt sets is deferred.
- **`test_f010_filtered_count.py`'s prefix-pair latent hazard.** The
  file's fixture (`suppliers`/`suppliers_has_classification`) would
  match `_supplier_pos_buyers` if it were ever passed to
  `synthesize_response` with a PO bucket and a buyer bucket. It is not
  — its tests call `_build_count_response` and `_filtered_bucket_pair`
  directly. No fix warranted; recorded so a future test that imports
  the fixture into a `synthesize_response` call sees it.
- **The country-path `total_available=None`.** V1's summary reads
  `Examined 25 of an unknown number of suppliers`. The suppliers tool
  honestly reports no total on the country-filtered path (the client-
  side filter caps the over-fetch; the pod-side `q=` carries only the
  server clause). Not a defect; a country-total would require a second
  probe the current single-clause pattern does not make. Recorded as a
  candidate finding if the wording ever matters.
- **Whether the display fallback for `synth_failed` matters for any
  other shape.** Deferred (see Deviations).
