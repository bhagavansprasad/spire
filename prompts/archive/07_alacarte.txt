# Spire prompt set — 07 A LA CARTE. Read by scripts/run_prompt_set.py.
# One prompt per line. Blank lines and lines starting with # are ignored.
#
# PURPOSE: regression set for the column-output feature shipped 2026-07-24.
# Unlike 00_dipstick (a depth sampler across the whole pipeline), this set
# exercises ONE feature in depth — the projected-column table, its address
# flatten, its graceful degradation, and the paths that must stay UNCHANGED.
#
# The feature: when a prompt names columns, the output is an aligned table
# of exactly those columns (in the order named), with the synthesizer's
# summary above it. If the synthesizer overruns the token cap, the run no
# longer aborts — it skips the summary and prints the table alone. Nested
# addresses flatten to an Address column when present.
#
# WHAT TO CHECK PER PROMPT (read the ANSWER, not the summary line):
#   - does the Intent carry the right `fields` list?
#   - does the printed table show EXACTLY those columns, in order?
#   - for same-entity columns: are all values populated (not em dashes)?
#   - for the address prompt: are addresses real strings, not em dashes?
#   - for the overrun case: does it print the "skipped" note THEN the table,
#     with no crash and no KeyError?
#   - for aggregation: is it UNCHANGED (no table, its own ranking format)?
#
# Anchors: supplier 1252 = Lee Supplies (US, ACTIVE, 25 addresses).
# Supplier 1262 = EIP Inc. 421 of 424 suppliers ACTIVE.

# ===== SAME-ENTITY COLUMNS — must populate fully, no em dashes =====

# — three columns on the Invoice root —
# All three are Invoice fields; the table must show all three populated.
Show me invoices for EIP Inc over 100000 with invoice number, amount, and date

# — six columns on the Invoice root —
# Wider request; the table must widen to all six, currency included.
Show me invoices for EIP Inc over 100000 with invoice number, amount, date, supplier name, supplier number, and currency

# — three columns on the Supplier root —
# Status was the column the old fixed formatter silently dropped; it must
# now appear.
List active suppliers with supplier name, supplier number, and status

# — one column —
# Minimal projection: a single named column.
Just the invoice numbers for supplier 1252

# ===== ADDRESS COLUMN — flattens the nested child, must be real strings =====

# — address as a column on a supplier list —
# Address is a child (expand=addresses). It flattens to one line per
# supplier (FormattedAddress, or City/State/Country when that is null).
# The synthesizer overruns on this one and is caught: expect the "skipped"
# note, then a populated Address column. This is the headline regression.
List active suppliers with supplier name, supplier number, and address

# — address column on a single supplier —
# Narrower set; the address must still populate.
Show supplier 1252 with supplier name, number, and address

# ===== GRACEFUL DEGRADATION — must not crash =====

# — the overrun case, stated plainly —
# Same as the address list above; kept here to name the behaviour under
# test. The synthesizer exceeds the cap, throws DegenerateOutputError, the
# run catches it and prints the table alone. A crash or KeyError is a fail.
List active suppliers with supplier name, supplier number, and address

# ===== PATHS THAT MUST STAY UNCHANGED =====

# — no columns named: default synthesizer output, no table —
# Empty `fields`; must take the old path and print the normal summary +
# structured list, NOT a projected table.
List active suppliers

# — aggregation with a column phrase: must NOT become a table —
# Aggregation sets `aggregate`, leaves `fields` empty, and formats itself.
# The "with supplier name and total" phrasing must not trigger the table.
Top 5 suppliers by invoice spend last year with supplier name and total

# — a plain by-id fetch: unchanged —
# No columns, single record; the normal path.
Show PO 2144 and its lines

# ===== EDGE CASES =====

# — a requested column that is NOT on the entity —
# "credit rating" is not a Supplier field. The parser drops cross-entity
# columns by design; the table shows the columns that survived. Document
# what actually happens rather than asserting a should.
Show supplier name and credit rating for active suppliers

# — columns naming a related-entity field (the join case) —
# "PO line number" on an invoice query lives on PO lines, not /invoices.
# This is the lifecycle/join case, out of scope for column projection —
# expect the survivors only, PO-line columns absent.
Show me invoices for EIP Inc with invoice number, PO number, and PO line number
