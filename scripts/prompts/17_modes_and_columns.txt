# Spire prompt set — 17 MODES AND COLUMNS. Read by scripts/run_prompt_set.py.
# One prompt per line. Blank lines and lines starting with # are ignored.
#
# PURPOSE: the F-003 + F-050 + F-004 regression set. All three landed on
# the same branch (phase-2-fix-F003-modes-reachable, PR #167, 2026-09-24).
#
# THE FIX: _TIER1 in context_assembly.py now names "modes" and "columns"
# alongside "core" and "refusals". Every router-scoped parse loads both
# cross-cutting teaching folders.
#
#   F-003 — three PO aggregation ops (po_value_by_supplier,
#           po_count_by_status, open_po_summary) lived only in
#           modes/m_aggregation.sysprompt; the parser either refused or
#           reached for the nearest visible op in a different block.
#
#   F-050 — columns/b_who_columns.sysprompt and b_column_fields.sysprompt
#           were unreachable; a column request like "supplier name and
#           country" was not recognised as one.
#
#   F-004 — with the aggregation ops visible, "top 5 suppliers by
#           purchase order value" routes to po_value_by_supplier instead
#           of misrouting to the comparison op
#           top_suppliers_invoiced_vs_ordered.
#
# THE RISK THIS SET STRESSES: modes/ carries SIX files, not one. The
# whole folder now loads for every routed parse — m_aggregation (the
# F-003 fix), plus m_comparison, m_count, m_open_invoices,
# m_topn_open_invoices, m_account_balance. columns/ carries two files.
# Nothing is scoped away any more.
#
# WHAT TO CHECK PER PROMPT — the summary line proves nothing; the
# Intent line does:
#
#   1. Does the Intent carry the right aggregate.op / count_only /
#      open_only / balance_only / fields?
#   2. For an aggregation prompt: is the op po_value_by_supplier /
#      po_count_by_status / open_po_summary, NOT
#      top_suppliers_invoiced_vs_ordered (the F-004 misroute)?
#   3. For a spend-vs-value prompt: is the op chosen by WHAT IS
#      MEASURED, not by the phrase pattern? "spend"/"invoiced" means
#      invoices (op='by_supplier'); "purchase order value"/
#      "committed"/"ordered" means POs (op='po_value_by_supplier').
#   4. For a column prompt: are the named terms in `fields`? The rule
#      from columns/b_who_columns is explicit — put the phrase in
#      fields, do NOT add 'Contact' to include.
#   5. For a refusal: is the flavor right, and does the message name
#      the specific term rather than the generic fallback?
#
# COST: the aggregation prompts paginate the full PO collection
# (~17,552 rows, ~36 pages, ~4 min each). This is an overnight set.
# The count/refusal/columns prompts are fast; the aggregations dominate.
# Roughly 30 aggregation prompts in sections 1-4 at ~4 min each is the
# cost driver. Everything else is under a minute per prompt.
#
# Anchors:
#   Supplier 1252 = Lee Supplies, US, ACTIVE, ~25 addresses
#   Supplier 1262 = EIP Inc
#   PO 2144 = OrderNumber 162352, EIP Inc, Closed, 2 lines
#   PO 162034 = Lee Supplies, Closed
#   Customer "ABC Application Software" = AccountNumber 26360
#   Customer "ABC Corporation Americas" = AccountNumber 26370
#   AR invoice CustomerTransactionId 300000248096352
#
# PRINCIPLE: if the pod has the data and the user asked a real
# question, SPIRE answers with the right op or the right column — not
# a refusal, not a misroute.
