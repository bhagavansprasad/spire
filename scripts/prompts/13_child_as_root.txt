# Spire prompt set — 13 CHILD-AS-ROOT. Read by scripts/run_prompt_set.py.
# One prompt per line. Blank lines and lines starting with # are ignored.
#
# PURPOSE: the F-041 regression set. Every prompt here NAMES A CHILD
# entity as the subject and gives the parent's identifier afterward.
# The user's intent is unambiguous: root on the PARENT and fetch the
# child via include. A refusal here is a bug — the pod has the data and
# the pipeline can fetch it when the parent is the target.
#
# PRINCIPLE (operator): if the pod has the data and the user asked a
# real question, SPIRE answers. No refusal, no redirect. The user's
# phrasing is the interface.
#
# HOW TO SCORE — the summary line proves nothing:
#   1. Does the Intent root on the PARENT entity (not the child)?
#   2. Does the Intent carry the correct include for the child?
#   3. Does the answer contain the child rows?
#
# EXPECTED-OUTCOME TAGS (in each section header):
#   ANSWER   child IS includable on this parent; must return rows
#   REFUSE   child is genuinely NOT includable — the tool is reverse-
#            only (search_suppliers_by_site_bu / by_classification),
#            so there is no forward fetch. Refusal is correct here.
#            See _NON_INCLUDABLE_ENTITIES in intent_validation.py.
#
