# Spire prompt set — 05 REFUSALS. Read by scripts/run_prompt_set.py.
#
# Out-of-scope and underspecified prompts, consolidated from every other
# set. All are FAST (they refuse at parse or plan time, no pod call), so
# this whole file runs in about a minute.
#
# A refusal is a PASS here. What matters is HOW it refuses:
#   - does it name what Spire actually supports?
#   - does it avoid guessing a nearby entity? Turning "contract renewals"
#     into a supplier list is the failure mode this set exists to catch.
#   - is the refusal flavor right (unknown_entity vs unsupported_filter
#     vs underspecified)?
#
# Design note: when the parser produces a degenerate Intent, the planner
# REFUSES rather than guessing. That is Design 3 working as intended, and
# a refusal here is not a defect.

# — entities Spire does not model —
show me contract renewals due next quarter
suppliers with net 30 payment terms
which suppliers have the best rating
suppliers with the highest quality score

# — subjective / judgment questions —
# These need an opinion, not a lookup. Refuse rather than rank.
who should we stop buying from

# — wrong granularity —
# PO line items exist as a concept but are only reachable via a PO id.
show me purchase order line items

# — missing a required root reference —
# Invoice queries need a supplier or a purchase order; without one the
# fetch would pull every invoice on the pod.
recent invoices

# — relative date windows are not supported —
# Must refuse rather than let the LLM compute a cutoff itself.
Purchase orders older than 6 months
